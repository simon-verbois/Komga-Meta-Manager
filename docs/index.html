01 / A thoughtful workflow

No surprises.
Just better metadata.

Fetching is only the beginning. KMM keeps proposed changes in its own catalogue, giving you a clear view of what happens next.

  1. 01

    Fetch the missing pieces.

    Choose your libraries and sources. KMM gathers metadata locally; fetching never changes Komga.

  2. 02

    Review it at your pace.

    Compare before and after. Keep a suggestion, discard a field, or add your own edit.

  3. 03

    Publish when it feels right.

    Send all changes or just selected series to Komga. You choose when your library is updated.

Existing values and locked fields are respected by default. Automatic publishing is an explicit choice.

02 / Your collection, your rules

Different shelves.
Different needs.

Manga series, scrolling webtoons, individual ebooks. Give each library a source list and metadata rules that fit.

  • ↗

    Start with a source template.

    Use built-in manga, webtoon or ebook templates. Reorder sources and save your own presets.

  • ↗

    Keep the details you care about.

    Fill empty fields, leave them alone or explicitly clear them. Customize a library or let it follow your defaults.

  • ↗

    Give ebooks their own treatment.

    Match individual books by ISBN or title and author. Review an edition yourself when a match needs a closer look.

03 / A place for the details

Less housekeeping.
More shelf satisfaction.

A browser-based workspace for the whole journey. Browse your catalogue, edit a description, follow a job. No YAML required.

A little help on repeat. Schedule a daily fetch or watch for new series. Automatic runs wait for review by default.

At home on your server. Docker and a browser are enough to get started. Configuration, edits and history stay in your local KMM database.

All KMM screenshots show the actual interface with an isolated fictional catalogue and original sample covers. They illustrate the development version; published releases may differ.

04 / Make yourself at home

Your next library
upgrade starts here.

Bring a running Komga server and an API key. KMM runs alongside it, with its own web interface and persistent configuration.

  1. 01

    Start the container.

    Save this as compose.yml in a new folder, then run docker compose up -d.

  2. 02

    Connect your Komga.

    Open localhost:8765, create your KMM account and test your server connection.

  3. 03

    Choose a shelf. Fetch. Review.

    Select your libraries and content types. Fetch metadata and review the proposals before publishing.

compose.yml
services:
  kmm:
    image: simonverbois/komga-meta-manager:latest
    restart: unless-stopped
    ports:
      - "8765:8765"
    volumes:
      - ./config:/config

Keep ./config backed up. It holds your settings, account, local catalogue and history.

A few good questions.

Does fetching change my Komga metadata?+

No. Fetch stores proposed metadata in KMM. Publish writes it to Komga. Automatic publishing can be enabled explicitly in Automation settings.

Which sources can I use?+

Manga and webtoon libraries use AniList, MangaDex and MangaUpdates. Ebooks use Open Library, Google Books and BnF. Google Books requires an API key. Availability and match quality depend on each source's catalogue.

Will KMM respect my existing edits?+

By default, existing values and Komga locks are preserved. Each library can inherit defaults or use its own rules. Manual KMM edits are preserved during fetching unless you explicitly choose to replace them.

Do I need Inkora to use KMM?+

No. KMM and Inkora are independent projects that work with Komga. Use KMM to manage metadata, and use whichever Komga reader you prefer.
